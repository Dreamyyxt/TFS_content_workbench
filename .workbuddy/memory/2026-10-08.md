## 10:00 「剪映模板换素材」可行性调研 + 引擎落地

用户问：不充火山 API 的钱，能不能走「剪映模板换素材」这条路。

### 关键结论：剪映 6+ 草稿加密，读不回模板
- 剪映 6.0 起草稿文件走 **AES-256 加密，且每份草稿一把独立密钥，密钥存在剪映内部数据库**
  （社区信息 + 本机实测一致）。Mac 端无可用解密方案（开源工具 `jy-draftc` 只支持 Windows，
  靠调用 `videoeditor.dll`）。
- 实测本机 `测试-备婚新娘`（被剪映打开并保存过）：
  - 根目录 `draft_info.json` → **加密**（base64 形态 `FH793fcI84…`，解出 40140 字节非 zlib/gzip）
  - `draft_info.json.bak`、`Timelines/<UUID>/draft_info.json`、`template-2.tmp` → 同样加密
  - 根目录 `draft_content.json` → **仍是明文完整 JSON**（9 段视频 / 16 文本 / 8 转场 / 3 轨）
  - `Timelines/<UUID>/template.tmp` → 明文，但只是**空草稿骨架**（canvas 0×0，materials 全空）
- **反向是通的**：剪映**能读明文草稿**（我们生成的草稿它能正常打开），
  只是它一保存就把 `draft_info.json` 加密。
- 剪映设置里**没有**关闭加密的开关（查过 `Config/commonSetting.ini`、`globalSetting`）。
- 云草稿目录 `com.lveditor.cloud.draft_*`、文本模板目录 `com.lveditor.textTemplate.draft` 均为空。

### 草稿结构（换素材的地基）
```
materials.videos[]      素材本体：id/material_id/path/material_name/width/height/duration/type
                        type = "video" | "photo"；photo 的 duration 固定 10800000000（3h）
tracks[].segments[]     时间轴片段：material_id 指向上面的 id
                        target_timerange（位置+时长，模板节奏）/ source_timerange（取素材哪一段）
                        extra_material_refs = [speed_id, transition_id, ...]
                        clip（alpha/flip/rotation/scale/transform）
materials.transitions[] 转场（叠化 350000us 等）
materials.texts[]       content 是 JSON 字符串，内含实际文字
```
**换素材 = 只改 materials 里的 path/type/w/h/duration，segment 一个字段都不碰。**

## 10:45 用户转向：给图片和视频 → 自动生成卡点视频

用户问「如果我就想要给你几个图片和视频，模型帮我生成卡点视频，用什么方案最好？」
结论：**本地全自动卡点引擎**（零成本、不用剪映、不用云 API）。已落地。

### 产出：`workbench/tools/make-beat-video.py`
给「一堆图片 + 视频」和「一首 BGM」，自动出 1080×1920 卡点成片。

**核心机制**
1. **librosa 节拍跟踪**（`librosa.beat.beat_track(trim=False, units='time')`）。
   实测精度：合成 100BPM 音频 → 检测 99.38BPM / 40 拍 / 拍距 603.7ms（真值 600ms），
   误差约 ±23ms（等于 hop_length 512 @22050Hz 的量化步长）。**够用**。
   去重规则：间隔 < 0.15s 的拍点合并（防八分音符被当拍）。
2. **切点全部落在真实拍点上**。`build_shots()` 的三条规则：
   - 开场镜头从 0 拉到第一个切点（比常规略长，读起来像开场）
   - 过长镜头均分（max_dur 4.5s）；过短并进前一镜（min_dur 0.30s）
   - **收尾段 < 中位镜头×0.75 就并进前一镜** → BGM 能完整放完不被硬切
3. **`choose_every()` 自动选密度**：不指定 `--every` 时，从 (1,2,3,4,6,8,12,16) 里挑
   使镜头数 ≤ 素材数 × `--max-loops`(默认2) 的最紧密度。**关键**：否则 5 张图 + 24s BGM
   会被切成 40 个镜头、每张图闪 8 次。
4. **xfade 链式串联的 offset 数学**（这是卡点不跑偏的关键）：
   第 i 段渲染时长 `r_i = shot_i + fade`（末段不加），
   `L_0 = r_0`，`L_i = L_{i-1} + r_i - fade`，`offset_i = L_{i-1} - fade`。
   代进去可得 `offset_i = Σ shot[0..i-1]` —— **切点精确等于节拍累计点，零累积误差**。
   末段 `r = shot`（不加 fade），所以总长 = Σ shots。
5. **音画对齐**：BGM 用 `atrim=start:end` + `asetpts` + `afade` 后封装，`-t` 锁总长。

**图片智能摆法 `image_border_color()`**（采样四边像素的中位色 + 离散度）
- 边框离散度 < 20 → **pad 留白居中**（logo / 品牌卡片，用图自己的底色补边）
- 边框杂乱且 |宽高比 - 9/16| / (9/16) < 0.15 → **crop 裁切填满**（手机竖拍）
- 其余 → **blur 模糊背景填满**（横拍照片 / 相机原片）：`split` 出 bg 走
  `scale=increase,crop,gblur=sigma=60,eq=brightness=-0.06`，fg 走 `scale=decrease`，再 overlay
- **pad 模式要把内容收进 90% 安全区**（`scale=cw*0.9:ch*0.9`），否则 zoom 1.11 时
  会切到 logo 边缘（踩过）。pad 模式动效幅度也降到 0.06，blur/crop 用 0.11。
- 合成在 **2 倍画布（2160×3840）**上做，zoompan 再缩回 1080×1920，避免放大发虚。

**色彩范围坑（重要）**：图片是 RGB 全色域、相机是 bt709 有限色域。
不统一的话同一条时间轴上各段亮度基准不同，切点处会闪一下。
实测 pad 模式产出 `yuv420p` 而 blur/crop 模式产出 `yuvj420p`（全色域标记）。
修法：所有链尾统一接
`scale=out_range=tv:out_color_matrix=bt709,format=yuv420p,setsar=1,setparams=range=limited:colorspace=bt709:...`，
输出再带 `-color_range tv -colorspace bt709 ...`。改完最终文件显示 `yuv420p(tv, bt709)`。

**两个 ffmpeg 坑**
- 单帧图片输入 + `fps` 滤镜 → **一帧都不输出**（"No filtered frames for output stream"），
  且 ffmpeg 退出码仍是 0、只写出 261 字节空 mp4。片尾卡必须用 `-loop 1 -i img -t N`。
  （zoompan 因为内部按 `d=N` 复制帧，所以不受影响，可以直接用单帧输入。）
- `xfade` 输出文件不能和输入同名（`Output same as Input #0 - exiting`）。加 `tag` 参数。
- `xfade` 硬约束：`offset + duration ≤ 第一个输入的时长`。接片尾卡时 offset 要取
  `vdur - fade` 而不是 `vdur`，否则越界。

**性能实测**：9 段素材 / 24s 成片，全流程约 40 秒。
