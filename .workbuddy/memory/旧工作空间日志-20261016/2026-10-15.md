## 评估「让别的电脑也能用视频制作」的可行性（只读调研，未改代码）

用户提出设想：任意电脑登录线上工作台 → 丢素材 → 在 Mac mini 上出草稿 → 晚上在 Mac mini 上挑稿发布。
旧方案分析声称「只要把前端 127.0.0.1 改成隧道地址，改一行前端即可」——**实读代码后确认此说法不准确**。

实测结论（文件+行号）：

1. `server.js:1510` —— `JY_LOCAL=1` 时 `server.listen(PORT,'127.0.0.1')`，**只绑本机环回**，外部机器的连接在内核层就被拒。要放开必须改绑 `0.0.0.0`（或引入 `JY_BIND` 环境变量）。
2. `jianying-api.js:111` —— `/session`（唯一发放 `userToken` 的入口）有**第二道硬闸**：
   `if (!local || !['localhost','127.0.0.1'].includes(urlHost(req)) || req.headers['x-jianying-studio'] !== '1') fail(403,'仅限本机剪映连接器')`。
   `urlHost()` = Host 头去端口（`jianying-api.js:256`）。走隧道时 Host 是域名 → **即使绑了 0.0.0.0 也照样 403**。
   → 所以这不只是「改一行前端」，服务端必须改**两处**（绑定地址 + session 主机白名单）。
3. `jianying-api.js:100-107` CORS/PNA 已写对：`knownOrigin` 认 `WEB_ORIGIN`（线上域名）+ 本机 Origin；
   且已回 `Access-Control-Allow-Private-Network: true` —— 这正是现在「https 网页调 http://127.0.0.1」能通的原因
   （127.0.0.1 属浏览器可信来源，不触发混合内容拦截）。
4. 反推：**Tailscale 裸 IP 方案（http://100.x.x.x）会被混合内容拦掉**，必须走 `tailscale serve/funnel` 拿 HTTPS 域名。
5. `index.html:248` 官方口径其实是「**换电脑就在那台电脑各跑一份本机服务**」，不是中央 Mac mini。
   用户要的是另一种架构；且剪映草稿/worker 天然绑 Mac mini，而「生成」（火山）只是 API 调用，理论上可搬云端。

结论给用户：能做，改动可控（服务端 2 处 + 前端 1 处），但真正成本在运维（Mac mini 必须常开 + 服务要手动双击启动，助手无法常驻）
与安全（隧道必须叠 Cloudflare Access/Tailscale 身份，否则等于公开 AI 管线与密钥通道）。
另提供 0 改动的兜底：远程桌面（屏幕共享/ToDesk/向日葵）到 Mac mini —— 本机 127.0.0.1 天然可用。

未落任何代码改动，等用户选路线。

## 追加：用户澄清真实诉求 + 云草稿链路调研

用户真实诉求（第二轮澄清）：**任意设备（店铺电脑、手机）上传素材并发起剪辑 → 任务落到家里的 Mac mini →
自动生成草稿并上传剪映云 → 在任何电脑的剪映里看到草稿并发布。** Mac mini 关机也能方便拉起。

### 云草稿这一段（新查，此前无记录）

- 草稿真实目录已定位：`~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft` ——
  技能的 `get_default_drafts_root()`（`scripts/utils/formatters.py:21`）自动探测到这个路径，
  **所以脚本写出的草稿天然落在剪映正规草稿目录里**，云备份才有机会接管。这点很关键。
- 云草稿索引目录：`~/Movies/JianyingPro/User Data/Projects/com.lveditor.cloud.draft_<抖音uid>`，
  里面只有一个 `root_meta_info.json`（云侧草稿清单），真身在云端按需拉。
- `com.lveditor.draft/root_meta_info.json` 的 `all_draft_store[]` 每条草稿带
  `cloud_draft_sync` / `cloud_draft_cover` / `draft_cloud_last_action_download` 三个布尔标志。
  实测本机两支草稿 `cloud_draft_sync` 全为 `false` → **自动备份当前没开**。
- **技能的 `scripts/cloud_manager.py` 只做「云端素材下载」（音乐/特效/视频素材），没有任何上传草稿的能力** ——
  指望代码把草稿推上云这条路不存在。
- 正解：剪映专业版自带**「草稿自动备份」**（首页右上角「全局设置」→ 草稿设置），
  开启后新草稿自动上传云端；可配「文件大小限制」避免塞满云空间。
  **纯 App 驱动、需登录账号、需 App 在线，脚本无法触发。**
- 跨设备是「上传 → 下载」两步，不是实时镜像：另一台电脑要在剪映「剪映云」里手动点下载。
- 未验证风险：脚本草稿引用的是 Mac mini 本地绝对路径，云端备份后素材能否在别的电脑正确还原，需实测。
