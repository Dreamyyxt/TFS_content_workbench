## 第五季内容工作台（产品化交付）

**需求**：把一次性排期交付，升级为可持续使用的在线工作台，含三块能力——
① 素材选择库（按账号特征列候选素材，源自平台风口，可手动刷新重新抓行业风口与流量词）
② 拍摄辅助（按所选素材出脚本）
③ 自动排期（按所选素材自动排拍摄与发布时间）

**技术方案**
- 后端：WorkBuddy 云服务（同一环境提供云数据库 + 免密钥大模型）
  - 应用 ID：`wbapp_OVXOIXh914a31yrMdLVAOD`；域名 `nail-content-workbench.app.workbuddy.host`
  - 免登录「共享工作区」策略：4 张表 RLS 均为 `FOR ALL TO authenticated, anon USING(true) WITH CHECK(true)`，
    用 `ops_name` 记录操作人而非 `owner_id`（避免 anon 下 `auth.uid()` 为 NULL 触发 NOT NULL 失败）
- 前端：纯静态 `index.html + styles.css + app.js`，SDK 走 CDN（`@tencent-ai/workbuddy-cloud-sdk@dev`）
- 云表：`materials`（素材，含 batch_id 批次）、`scripts`（脚本+合规结果）、`schedules`（排期+plan_batch 批次）、`trend_snapshots`（风口快照）
- 发布：`workbuddy_sites_deploy`（静态站点，复用 appId 保住预留域名与云服务 Origin）

**关键实现事实**
- 大模型**只支持流式**（`stream:true`），必须自己拼 SSE chunk；一次性 JSON 也走流式再解析
- 必须传 `system` 消息作为 `messages[0]`，否则报错
- 「刷新风口」约需 2–3.5 分钟（生成 19 条素材的 JSON），「生成脚本」约 100 秒；UI 已做流式进度展示
- 合规自检为**本地词库**扫描，需排除脚本自带的「合规提示」段落，否则会把它列举的反面词例当命中（已修）
- 脚本卡片合规等级改为**实时计算**，避免入库口径与展示漂移

**踩过的坑（重要）**
1. `workbuddy_sites_deploy` 对已有线上链接的目录，第二次发布需用户当次明确同意（`userAskedToPublish`），
   且不能自问自答绕过；用 AskUserQuestion 取得明确同意后再调。
2. 前端 `bind()` 里引用了 HTML 中不存在的元素（漏写底部「待制作篮子」），导致整个 `boot()` 抛错、
   页面永远停在初始文案「连接中…」。**教训：新增 JS 引用 id 后，务必和 HTML 做一次交叉校验。**
3. 浏览器自动化验证：`agent-browser install` 下载 Chrome 会超时，但本机 `/Applications/Google Chrome.app`
   与 `~/Library/Caches/ms-playwright` 的 chromium 可直接被复用，`agent-browser open` 即可用。
   本地 `python3 -m http.server` 起的服务，升级后的浏览器进程**访问不到**（网络命名空间不同），必须走线上域名联调。
4. 排期算法需保证不变量「拍摄日 < 发布日」：发布日要右移到首个拍摄日之后，且拍摄日分配要按负载均衡
   （原「取最近拍摄日 + 容量上限」的写法会把素材挤到未来拍摄日，出现发布日=拍摄日）。
