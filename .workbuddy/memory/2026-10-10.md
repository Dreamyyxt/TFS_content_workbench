## 红狐官方 MCP 调研（2026-10-10 晚，为「抖音/小红书改用红狐 MCP」需求做的技术摸底）

**关键结论：红狐有官方 MCP，且有远程 HTTP 模式 → 已发布的工作台可以作为 MCP 客户端直接调用。**

- 远程端点：`https://mcp.redfox.hk/{platform}/mcp`（platform = douyin / xiaohongshu / …），
  Streamable HTTP，MCP 协议版 `2025-06-18`。
- **鉴权**：请求头 `REDFOX_API_KEY: <ak_...>`（或 `Authorization: Bearer <ak_...>`）。
  无 key → 401 `{"error":"auth_failed"}`。**不需要 `Mcp-Session-Id` 也能 tools/call**（实测带 session 更稳）。
- 本地 stdio 形态为 `uvx redfox-douyin-mcp` / `uvx redfox-xiaohongshu-mcp`（Python≥3.10）。
  **但线上发布的工作台没有这个进程 → 只能用远程 HTTP 模式**（REST 直连是 MCP 的底层，功能等价）。
- 工具面：抖音 16 个、小红书 15 个（工具名单见当日对话）。

**实测可用（返回真实数据）**
| 工具 | 结果 |
|---|---|
| `douyin_search_articles`（优质库） | ✅ 20 条/页，字段全（点赞/收藏/评论/音乐/作者/链接） |
| `douyin_search_works_wide`（广域库） | ✅ 10 条（覆盖广但仅收热门） |
| `xiaohongshu_search_articles`（优质库） | ✅ 20 条/页，字段全（收藏/评论/正文/话题标签/链接） |
| `xiaohongshu_search_hot_notes`（爆款洞察） | ✅ 返回 `articles` + **`hotTopics`** + **`relatedSearches`** + `total`，最适合找风口 |

**红狐服务端 bug（非我方问题，暂避）**
- `douyin_get_daily_hot_rank`、`xiaohongshu_get_daily_hot_rank` →
  `Error calling tool: structured_content must be a dict or None. Got list: [...]`
  （红狐把 list 塞进 structuredContent，MCP SDK 校验失败）。**榜单类工具当前不可用，需容错降级到搜索类。**

**能力缺口（重要）**：抖音 MCP **没有「热搜词条榜」**（只有作品榜）→ 工作台现有的「抖音热榜（热词）」
只能继续走原 REST `/story/api/hotSpot/getListByPlatform`。这一点已向用户确认取舍。

**调用耗时参考**：initialize ≈1.0–1.5s；单次 tools/call ≈0.5–4.8s（爆款洞察最慢）。6 关键词 × 2 平台约 15s。
