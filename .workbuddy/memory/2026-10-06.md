# 2026-10-06 工作日志

## 工作台问题诊断（用户提出 4 个问题，已完成排查）

**Q1 刷新风口用什么模型 / 为什么不是实时抓取**
- 代码 `ensureModel()` 取 `models.list()` 里第一个 `disabled !== true` 的模型 → 实际用的是 **`auto`（Auto，默认路由模型）**，
  其属性 `onlyReasoning: true` + `reasoning.effort = "high"`，**思考无法关闭**，这是"慢"的根因。
- 模型端**无联网能力**：`cloud.llm` 只有 chat.completions（仅流式），不暴露检索/浏览工具；
  "实时抓取"只能由 agent 侧 WebSearch 或定时任务把外部数据喂进来。原始实现是纯模型推演，不是抓取。

**Q2 模型耗时（同题实测，同一页面 SDK 调用，脚本写入 `window.__bench` 后用短命令轮询取回，
   避免长阻塞导致 agent-browser 守护进程 `Resource temporarily unavailable`）**
- 非流式不被支持：`request_stream_required`（`stream must be true`）。
- 实测结果（同一 prompt：写 6 镜头分镜表）：
  | 模型 | 首字 | 总耗时 | 正文 | 思考 |
  |---|---|---|---|---|
  | **deepseek-v4.1-flash** | **1.0s** | **3.1s** | 542 | 0 |
  | hunyuan-2.0-thinking | 13.1s | 16.9s | 1004 | 2027 |
  | glm-5.3-flash | 19.2s | 28.5s | 624 | 2129 |
  | **auto（原默认）** | **37.8s** | **42.3s** | 650 | **5554** |
- 结论：auto 最慢（思考流 5554 字），换 flash 档提速 10 倍以上。
- 文档确认 `create()` 可传参数仅：`temperature / top_p / repetition_penalty / response_format /
  stream_options / conversationId / signal`；`top_k` 传了无效，**无 reasoning_effort 参数** → 提速只能换模型。

**Q3 「删除点了没反应」根因（已复现并修复）**
- 删除按钮走 `if (!confirm(...)) return;`——依赖**浏览器原生 confirm**。
- 实测：点击删除后页面 JS 线程被原生弹窗阻塞（agent-browser 命令直接卡死被 SIGTERM）。
- 在 WorkBuddy 内置预览面板（iframe）中，原生 confirm/alert 被静默拦截并返回 false → 表现为"点了没反应"。
- 修法：新增 `askConfirm()` 页面内确认条（`.confirm-bar`），彻底去掉原生弹窗依赖。

**Q4 看板方案（用户选定：全做 + 手动录入）**
- 整体进度看板：数据全部来自现有表（素材/脚本/排期/数据看板），含生产漏斗、账号节奏达成率、拍摄日负载、
  未来 7 天发布计划、风险与待办。
- 视频数据看板：**手动录入**（表单 + 明细表 + 达标标记 + 选题回溯）。截图识别与平台 API 本轮未做。

**合规自检的第二个真 bug（本轮新发现并修复）**
- 现象：几乎所有生成脚本都被判 `block`，命中词全是脚本自带「合规提示」段落里列举的反面词例。
- 根因：模型不把这一节写成 Markdown 标题，而是挂在「发布配置」下的列表项（`- 合规提示`），
  而旧 `scanTarget` 只认 `^#{1,4}\s*` 标题 → 排除逻辑失效。
- 修法：重写 `scanTarget`，识别标题/列表项/加粗小标题三种写法，并按缩进判断该节结束位置
  （同级兄弟项若本身在讲风险则仍算该节内容）。写了 5 个用例单测全部通过：
  真实脚本→pass、标题式→pass、正文含极限词→block、正文含提示词→warn、合规提示在中段→后续小节仍被检查。
- 脚本弹窗的风险横幅改为列出命中词 + 上下文片段，方便人工判断而非盲信。

**验证记录（线上实测，全部通过）**

## 第二轮：接上「真联网」（工作台 v3）

**用户诉求**：思考过程要放出来 / 必须联网（"不联网有什么用，一点都不能抓住实事"）/ 模型用 deepseek flash /
看板 + 违禁词删除 bug 要修。

**关键结论：云端大模型本身不能联网**
- `cloud.llm` 只有 `chat.completions`（仅流式）。SDK 虽然会透传 `delta.tool_calls`，
  但文档明确写「SDK only passes tool deltas through; it does not execute tool calls」——
  工具执行属于业务层，浏览器侧没有可用检索接口，模型端**没有内置 web search**。
- 外部公共搜索/代理接口在沙箱里全部 502（r.jina.ai、duckduckgo 均不可达），
  所以「页面内直连公网搜索」这条路走不通。

**因此确定的架构：联网采集器 → 云端表 → 工作台读取**
1. 采集器（agent 侧 WebSearch）把真实来源整理成 snapshot JSON；
2. 写入云表 `trend_snapshots`（`source:'web'`，`payload` 是 jsonb，装 sources/sections/materials）；
3. 工作台「同步联网风向」按钮读最新 web 快照，把 payload.materials 落成素材卡；
4. 每日 09:00 自动化 `第五季 · 每日联网风向采集` 保新鲜（id `67ca0668-4b8e-4d89-bcd1-911ae92a527c`）。

**云端库可以脱离浏览器直接读写（重要能力）**
```
curl "$ENDPOINT/.cloud/database/rest/<table>" \
  -H "x-wb-webapp-access-key: <publishableKey>" \
  -H "Origin: $ENDPOINT"
```
- 鉴权头是 **`x-wb-webapp-access-key`**（不是 apikey，不是 Authorization；用错会 401 invalid_client）。
- PostgREST 语法：`?select=*&order=created_at.desc&limit=N`、`POST` 带 `Prefer: return=representation`、
  过滤删除 `?batch_id=in.(A,B)`。
- 通用写入脚本：`workbench/tools/push-trend.py <snapshot.json>`。

**表结构（已确认）**
- `trend_snapshots`：id / batch_id / summary / keywords / payload(jsonb) / source / ops_name / created_at
- `materials`：id / batch_id / account / platform / title / angle / content_form / goal / hook /
  keywords / trend_reason / priority / selected / ops_name / created_at
- batch_id 前缀约定：`W` 联网采集 / `B` AI 推演 / `S` 内置底稿

**本轮改动**
- `index.html`：风向面板重做（来源徽标 + 采集时间 + 7 个主题要点 + 可点开的来源列表 + 思考过程提示）；
  按钮改为「同步联网风向（主）/ AI 推演一批（兜底）/ 载入趋势底稿」

  renderTrend（重写） / trendPayload / webMaterialsOf / trendIsStale / relTime / absTime /

  且 prompt 会用 `trendGrounding()` 把联网风向当事实底稿喂进去（模型只做展开，不编数据）

**数据的真实性设计**

- 素材卡的 `trend_reason` 直接引用联网结论；徽标区分「联网抓取·实时 / AI 推演·非实时 / 内置底稿·非实时」；

**首轮采集结果**（batch `W18718349`，id 9）：18 个来源 / 7 个主题 / 33 条要点 / 23 个流量词 / 19 条素材
（6+5+4+4）。核心风向：棕调 + 一处发光点（玻璃珠·绸缎猫眼）、琥珀晕染换季声量最大、
美睫妈生感（0.05mm / 8–10mm / C 翘 / 密度≤七成）、抖音必须挂 POI + 地域词、小红书看收藏私信不看赞、
10/31 万圣节是周六且风为「贵气暗黑」、行业热点「美睫胶水超八成检出甲醛」可做信任内容。
