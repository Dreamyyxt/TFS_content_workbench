# 创作者中心 Excel 导入

数据看板增加「导入 Excel 数据」，支持抖音创作者中心的原始「作品列表导出.xlsx」，同时接收视频和图文。沿用 `design/discover-create` / PR #13，不新增项目工作目录。

## 操作

1. 打开数据看板，点击「导入 Excel 数据」，选择 .xlsx 文件。
2. 选择这份表所属的工作台账号。文件没有账号名，系统不根据标题猜测所属账号；可选抖音或双平台的启用账号，导入平台固定为抖音。
3. 核对作品、时间、指标及处理方式。可展开「其他导出指标」，或取消勾选不需要的作品。
4. 默认跳过已导入的作品；确需刷新时，选择「更新本次表格有值的指标」，使用较新的导出表。
5. 点击「确认导入」。之后在作品的「查看导出明细」里查看完整完播率、平均时长等扩展指标。

原始文件在浏览器 Worker 中解析，不上传给第三方、不调用模型、不执行单元格公式。核对已有记录会读取工作台云端数据；只有确认导入才写入解析后的记录。原有链接录入和手动录入继续可用。

## 字段

| 导出字段 | 工作台处理 |
| --- | --- |
| 作品名称、发布时间 | 标题与发布日期；完整发布时间保留用于核对重复 |
| 播放量、点赞量、评论量、收藏量、分享量、粉丝增量 | 对应现有数值指标 |
| 5s 完播率 | 5 秒完播率，比例转为百分数 |
| 完播率 | 完整完播率；绝不写入 3 秒完播率 |
| 封面点击率、2s 跳出率、平均播放时长、主页访问量 | 保留在导出明细 |
| 体裁、审核状态 | 原样保留；不自动排除非公开作品，用户可取消勾选 |
| 表中未提供的指标 | 新记录明确写 null；更新时保留已有值 |

例如 `0.333333` 显示为 `33.33%`；含 `%` 的文本按百分数读取。真实零值保留，`-` 等空值不当成零。数值异常、无效日期、公式行列在错误清单中，不静默改成零。

## 去重和写入

- 以账号、平台、完整发布时间、原始标题识别已导入作品；不同账号隔离。
- 文件内完全相同的重复行仅保留一条；同一作品有不同数据时不自动选择其中一条。
- 与历史手填记录同日同标题，或同时间但标题变更的记录，标为待核对，暂不自动合并。
- 确认前重新读取云端；同浏览器支持 Web Locks 时互斥导入同账号。此方案不提供跨设备数据库唯一约束，避免多设备同时导入同账号。
- 更新使用字段补丁，保留备注、未提供指标、原视频链接及排期关联。累计指标替换，不叠加。
- 逐条写入、展示进度；失败或无法确认写入结果时停止，报告已确认保存数。重新核对后可重试，默认跳过已存在作品，不整批盲目重放。
- 沿用现有 `video_metrics` 表：基础指标使用原列，导出明细与去重来源使用 `note` 中的版本化 JSON envelope（`tfs_metric_export: 1`）。界面只显示用户备注，编辑备注会保留来源元数据；普通旧备注兼容。无数据库迁移。

## 当前范围

只保证本文所述抖音作品列表格式；不是任意 Excel 或其他平台通用导入器。单文件限制 10 MB、2000 条、64 列；多个匹配的作品工作表会要求用户拆分。为避免已有数据查询被截断后误判重复，单账号接近现有 1000 条核对上限时停止导入，并提示减少数量；该容量限制需后续分页方案扩展。原看板读取仍保留既有最多 1000 条记录的限制。

Excel 不含作品链接或作品 ID，不能凭标题自动补齐链接或可靠关联排期。没有 3 秒完播率、曝光、私信、商品点击、核销等指标时，保持缺失。

## 验证与依赖

- 用户提供的真实文件：107 条全部解析成功、0 条错误；在浏览器 Worker 中再次预览验证，真实数据零写入、未复制进仓库或截图。
- Node 回归 90 项通过，新增覆盖比例、日期/时区、缺失与零、公式/损坏文件、ZIP 边界、重复冲突、账号隔离、更新保留字段、失败重试与容量边界。
- 浏览器专项：5 种宽度，账号必选、逐条勾选、显式保存/更新、重复导入、跨账号、编辑备注保留扩展指标、部分成功后重试、读取失败、无效文件。
- 原 analytics 专项（7 种宽度）和链接导入/排期专项通过。所有云端写入都使用隔离模拟数据库，未写生产数据。
- SheetJS CE 0.20.3 mini 从官方 CDN 固定版本下载并随仓库托管，Apache-2.0 许可；仅导入时加载。来源与校验见 `workbench/vendor/README.md`。
