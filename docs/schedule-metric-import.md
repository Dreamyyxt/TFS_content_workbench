# 品牌居中、排期边界与作品链接录入

沿用 `design/discover-create` 和 PR #13，不新增工作目录。

## 可见改动

- 第五季原版 logo 下的「内容工作台」居中，包括手机顶部导航。
- 拍摄窗口从用户选择的日期起算，持续所选周数；仅使用窗口中的周二、周五。发布至少晚于拍摄一天，并按账号周更频次向未来顺延，同一账号不会因日期顺延挤在同一天。为了准确表达现有功能，选择项改称「拍摄周数」，页面明确发布可能超出该窗口，所有选中内容均继续安排。
- 例如起始日期 `2026-10-17`：首个可用拍摄日为 `2026-10-20`，不会再出现 `10-13` 或 `10-16`。旧排期记录不自动修改，重新生成后显示新批次；历史数据保留。
- 数据看板增加「作品链接 → 读取链接数据 → 核对预览 → 填入表单 → 保存数据」。可粘贴完整链接或单条链接的分享文字，使用已有红狐密钥配置。
- 读取不会写数据库；填入只替换预览中返回的字段，其他已有字段保留。修改链接、取消表单、切换编辑记录时，未完成请求与旧预览失效。读取失败可继续手动录入。
- 未填写数值保持 `null`；真实的 `0` 保留；不将未知值、缩写（如 `1.2万`）、账号总获赞当成准确的作品数据。新记录未读取到发布日期时不默认今天。

## 数据能力与边界

复用 RedFox MCP 的 `douyin_get_work(work_url)` 和 `xiaohongshu_get_work(work_link)`。参考官方定义：

- https://github.com/redfox-data/redfox-mcp/blob/main/packages/redfox-douyin-mcp/src/redfox_douyin_mcp/server.py
- https://github.com/redfox-data/redfox-mcp/blob/main/packages/redfox-xiaohongshu-mcp/src/redfox_xiaohongshu_mcp/server.py

映射标题、平台、发布日期、点赞、评论、收藏、分享；缺失项不填。读取范围取决于数据源收录和返回值，不保证所有链接可读。短链接由数据源处理；失败时提示尝试浏览器打开后的完整作品链接。接口可能返回采集快照，不能保证与平台此刻完全一致。

播放量、曝光、3/5秒完播、私信、商品点击、核销和涨粉不从这条公开详情链路导入，需要后台数据另行补充。本次没有实现账号授权、定时同步或批量导入，也没有请求用户浏览器中的平台登录凭证。

服务端新增 `POST /api/metrics/import`；只接受允许的平台域名，固定访问红狐 MCP，不由本机直接抓用户提供的 URL。密钥复用请求头或服务端环境变量，不写库、不记日志；错误消息不回显上游请求或凭证。该适配器源文件不对外静态提供。

## 验证

- Node 回归 81 项：日期边界（全部星期、跨年、闰日、1–3 周、账号频次）、字段映射、缺失值、上海日期、域名校验、MCP 参数、HTTP 请求边界。
- 新浏览器专项：5 种宽度的品牌居中与表单溢出，预览与保存分离，部分数据保留，失败重试，取消和失效响应，编辑已有记录，以及截图日期排期。
- 原有 analytics / planner 浏览器专项通过（7 / 6 种宽度）。
- 全部数据库、平台和 MCP 数据使用隔离模拟，未请求真实账号作品，未写线上数据。真实平台返回与账户权限仍需上线后用实际作品验收。
