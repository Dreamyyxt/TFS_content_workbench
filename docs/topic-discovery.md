# 关注主题与分步选题

分支：`feature/topic-discovery`，基于已合并的 `main`（`1b821bf`）。

## 使用方式

1. 在风口选题页添加关注主题，如 enoi、maogel、婚甲。支持逗号分隔、忽略大小写去重，每个主题最多 40 字，最多 8 个。可以保存主题，也可点击获取风向时一并保存。
2. 点击「获取最新风向」。主题同时进入公开搜索和现有红狐站内检索，与账号关键词及日历词合并；站内作品保持近 7 天过滤。
3. 查看本期发现、关注主题返回的来源数量及原文。没有近 7 天来源会明确提示；关注主题本身不作为热度证据。
4. 点击「按账号生成选题」。复用本期保存的风向、真实来源及门店档案，按照已启用账号的定位、语气和数量生成；经过 Humanizer 改写与规则复查后才入库。
5. 在店铺档案的账号矩阵中新增或删除账号，再保存规则。删除只使账号退出后续生成，历史选题、脚本、排期保留，可恢复。至少保留一个启用账号。

修改关注主题不会改变已经采集的那一期风向。生成区提示使用的采集时间、当期主题和账号数量；若关注主题已改动，会提示重新获取风向以纳入新主题。

## 实现与失败处理

- 关注主题保存在现有 `store_profile` 的 `profile_key=trend_topics` 记录中，使用 `note` 保存版本化 JSON；档案读取排除该设置记录，无新增数据表。
- 公开采集通过 `/api/trend/collect?topic=...` 传参；服务端做输入校验，加入近 7 天搜索计划，保留来源的查询主题归因。红狐使用原关键词接口，自定义主题优先，前端每次最多 16 个合并关键词。
- 风向快照保存本期主题、来源、检索词和归纳结果，不含自动生成的选题。采集失败仅回读旧快照，不再导入旧快照里的素材；首次打开空库也不自动写入示例选题。
- 自动归纳失败仍保存已获取的原始来源，并明确提示归纳未完成。没有有效来源或热榜则保留上一期。
- 最新真实风向单独查询，避免被多次生成记录挤出最近 30 条列表。
- 生成分两次模型调用：账号初稿、Humanizer 改写与复查。`topic-workflow.js` 验证账号与数量、非空字段、重复标题，并将改写限制在标题、切入角度、开头和依据；账号、平台和关键词由原稿保留。
- Humanizer 基于项目已有的中文规则，并参考 [Humanizer SKILL.md](https://github.com/blader/humanizer/blob/main/SKILL.md) 的检查、改写、复查流程。通过现有模型服务运行，没有引入新的第三方执行服务。规则扫描只能捕捉一部分表达问题，不能保证文案质量或事实完全正确。
- 改写失败、条目遗漏或明显套话未通过复查时，不写入选题库；软性表达建议可在选题详情查看。
- 生成记录保存关联的风向批次与 Humanizer 阶段。选题保存成功但记录归档失败时仍明确说明选题已保存；保存后列表刷新失败提示刷新查看，避免重复生成。
- 主题保存失败保留草稿；保存前检查其他设备的修改，已有记录更新附带时间戳条件。账号删除需页面确认，保存失败保留待保存列表。

## 验证

- 64 项 Node 测试通过：包括主题规范化和上限、搜索优先级、公开查询传入与来源去重归因、近期/旧/无来源区分、账号数量和 Humanizer 身份保护。
- 新增 `workbench/tools/topic-discovery-browser-check.cjs`：主题持久化/失败/冲突、双通道参数、采集不生成、生成不重新采集、Humanizer 正常与异常、空采集、归纳与快照保存失败、选题入库失败/归档失败/刷新失败、账号新增/取消删除/删除/恢复/保存失败、自定义账号参与生成、历史内容保留、空库不自动写入、5 种屏幕宽度。
- 原全站浏览器回归通过：9 页 × 5 宽度及选题保存、脚本传入制作、导航、周历、弹窗焦点、减少动态效果。
- [离线功能预览](../outputs/topic-discovery/preview.html)使用隔离测试数据。没有调用真实搜索或付费模型，没有变更线上主题设置、账号或内容。

运行专项：`PLAYWRIGHT_MODULE=/path/to/playwright node workbench/tools/topic-discovery-browser-check.cjs`。默认使用 `http://127.0.0.1:4318`，可通过 `STUDIO_URL` 与 `STUDIO_ARTIFACT_DIR` 覆盖。
